## 聚合规则

由 15 版工作流 Step 5 自动执行，规则：

1. 遍历 `.agent-workflow/modules/*.md`（排除 `_` 前缀与 `-guide.md`）的「下游数据/接口调用」章节
2. 提取「消息队列」段落的每一条：
   - 标注 `发布` → 所在模块进入对应 topic 的**发布方**列
   - 标注 `订阅` → 所在模块进入对应 topic 的**订阅方**列
3. 按 topic 名去重合并，若同一 topic 有多个发布/订阅方 → 逗号分隔列出
4. 更新 `<!-- LAST_ANALYZED -->` 头为聚合当日日期

## 一致性告警

<!-- CONTENT_START: consistency_warnings -->
> 由聚合过程自动填充。以下告警**不会阻止**台账更新，但需要人工复核。

**告警类型**：
- ⚠️ **多发布方**：某 topic 有 2 个及以上发布方 → 语义可能不清
- ⚠️ **孤儿 topic**：有发布方但无订阅方 → 订阅方可能未建档
- ⚠️ **无发布方订阅**：某模块声明订阅但无人发布 → 可能是外部系统发布，或订阅方档案信息陈旧

## 使用协议（供 Agent 参考）

- **正向链路推导**（16 Step 2.1）：读到某模块「下游数据/接口调用」中的 MQ **发布** → 查本表 → 订阅方模块作为链路下一跳
- **反向影响面推导**（16 Step 2.2）：读到某模块「入口点」中的 MQ **消费** → 查本表 → 发布方模块作为影响链上游
- **数据反查**（16 Step 2.3）：用户问"谁发布/订阅了 topic:xxx" → 直接查本表返回
