# 🔗 业务调用链档案索引

> ⚠️ **Agent 强制规则**：每次完成任何调用链推导（16 号工作流 Step 5）后，**必须立即同步更新本文件的索引表**。
> - 首次推导 → 在索引表追加一行，`STATUS = DERIVED`，填全字段
> - 用户确认无误 → 将 `STATUS` 升级为 `VERIFIED`
> - 沿途模块档案有更新 → 由 15 Step 5.5 联动置为 `STALE`（`时效状态` 列同步刷 🔴）
> - 用户显式作废 → `STATUS` 置为 `ABANDONED`，保留档案不删除

> 本文件是 `chains/` 目录的**入口索引**，是 Agent 复用已推导链路的唯一入口。
>
> **Agent 使用规则**：接到"画调用链 / 影响面 / 数据反查"类任务时先读本文件，通过「起点」「类型」「关键词」三列匹配已存在链路；命中且非 `STALE` / `ABANDONED` → 直接加载对应链路档案复用，跳过 16 Step 1-5 重推。

## Agent 按需加载规则

```
1. 接到链路推导类任务时，先读本文件（index.md）
2. 按下列优先级匹配已推导链路：
   ① 类型 + 起点/入口精确匹配 → 命中即复用（前提：STATUS ≠ STALE/ABANDONED）
   ② 类型 + 关键词模糊匹配 → 列出候选让用户选
   ③ 无匹配 → 走 16 号完整推导流程，落档后回填本索引
3. 加载命中档案前，必须校验：
   - STATUS ∈ {DERIVED, VERIFIED}
   - 时效状态 ∈ {🟢, 🟡}（🔴 STALE 时给出提示，让用户决定是否重推）
4. 命中复用时，向用户显式声明："已加载 chains/<slug>.md（推导时间: X, 状态: Y）"
```

**示例**：用户说"画一下下单支付的全流程" → 类型=forward + 关键词`order,pay` → 命中 `chains/order-pay-forward.md`（VERIFIED / 🟢） → 直接展示档案中的 mermaid 图，不再重扫代码。

## 维护规则

| 操作 | 需更新的字段 |
|------|------------|
| 新增链路（首次推导落档） | 追加一行，`STATUS = 🟡 DERIVED`，「时效」= 🟢，「最后推导」= 今日，「最后核对」= `-` |
| 用户确认核对通过 | `STATUS = 🟢 VERIFIED`，「最后核对」= 今日 |
| 沿途模块档案有更新（由 15 Step 5.5 联动触发） | `STATUS = 🔴 STALE`，「时效」= 🔴，同时在链路档案「变更历史」追加一行说明失效原因 |
| 用户显式作废（如业务下线、入口废弃） | `STATUS = ⚫ ABANDONED`，保留档案不删除，「时效」置为 🔴 |
| 重新推导覆盖旧档案（`刷新调用链档案 <slug>`） | `STATUS` 回到 🟡 DERIVED（等待用户再次核对），「时效」= 🟢，「最后推导」= 今日，同时在「变更历史」追加一行 |

> ⚠️ 禁止直接删除索引行（即使链路已作废），应通过 `STATUS = ABANDONED` 软删除。这样保留了历史核对痕迹，可追溯 "这条链路曾经是什么样的"。

## 关键词填写规范

关键词用于 Agent 语义匹配，填写时遵循：

- 用英文逗号分隔，**不超过 8 个**
- 包含：入口标识（HTTP 路径 / 函数名 / topic 名）、涉及的核心业务术语、涉及的核心模块名
- 示例（下单支付主链）：`order,pay,payment,checkout,下单,支付`

## 与 15 模块台账的联动（级联失效）

本索引与 [`modules/index.md`](../modules/index.md) 是**联动**关系：

- 每份链路档案头部都有 `SOURCE_MODULES_SNAPSHOT` 字段，记录**推导时**沿途各模块的 `LAST_ANALYZED` 快照
- 15 Step 5.5 每次刷新某模块档案后，会扫本索引，把所有 `SOURCE_MODULES_SNAPSHOT` 中包含该模块的链路自动置为 `STALE`
- Agent 加载 `STALE` 链路时**只提示不自动重推**，由用户显式触发 `刷新调用链档案 <slug>` 来重推（避免为一次改动触发大量 tokens 重推）
